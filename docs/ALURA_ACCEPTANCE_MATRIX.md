# Alura acceptance matrix — MediFlow backend

This matrix reconciles the explicit evaluation checklist with the current backend, tests, and project documentation. It records evidence in the repository; it does **not** certify clinical accuracy, safety, or live deployment. Test files and historical run notes are not evidence that tests were executed during this task.

## Reading guide

- Read each row from requirement to observable outcome, then verify the cited source and test locations.
- **Implementado (evidencia)** means the repository contains the described implementation and a focused test artifact; it does not mean that test was run now or that an external service was verified.
- **Parcial** means there is concrete implementation or documentation, but part of the requirement lacks implementation, current verification, or complete scope.
- **Pendiente** means no sufficient implementation evidence was found for the required outcome.
- **No verificable** means the repository does not provide enough evidence to determine the claim.
- To verify locally, from `backend/`, run the relevant focused tests named below with `uv run --locked pytest -q <test-file>`. The project also documents `uv run --locked pytest -q` for the full suite. Neither command was run for this documentation task.

## Evidence limits and next step

This is a repository evidence inventory, not a general test report. Recorded focused evidence includes the synthetic T7.1 pipeline test and T7.2 review/ingestion/persistence tests; T7.2 used SQLite and neither task made external provider calls or remote Neon/OCI operations. A prior authorized run verified one synthetic Neon/OCI record across independent application processes; it was not repeated. Confidence scores and literal source quotes describe extraction metadata/evidence, not calibrated risk or clinical correctness. A human reviewer remains the authority for review and routing decisions.

**Next:** T2.4 medication name/dose fields are implemented with literal evidence, optional nulls, and focused synthetic tests; no live Gemini call was made. T7.1's focused pipeline run passed 10 tests; T7.2's local review/ingestion/persistence run passed 69 with 3 deselected. These scoped runs do not complete overall Alura acceptance. T7.2 used SQLite and retrieved the original through the storage adapter, not HTTP; no remote Neon/OCI or external provider calls were made for T7.2. T7.3's six-case HTTP attempt was inconclusive after 30 seconds without progress and was interrupted; no test count, traceback, or body-start evidence was produced. T3 is verified only for the separate previously tested synthetic cross-process Neon/OCI scenario. The two Linux/WSL HTTP tests for T2.3 remain deferred, open, and unapproved. Authentication/roles and cancel/replace remain deferred; audio and JEV remain later/optional. T2.2 remains a technical possible-conflict flag for human review, not a clinical conflict adjudicator.
